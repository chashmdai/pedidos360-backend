Evidencia E-07. Publicación de un pedido en Kafka desde Orders

Objetivo
Trazar un pedido desde la SPA hasta su mensaje en el tópico.

Indicador asociado
EP5: productores (14 %). EP6: flujo de producción y consumo (12 %); diseño de eventos (6 %).

Entorno
AWS cuenta 647660738152 (us-east-1), EC2 i-01bcf3ef9d3a64d4e (t3.large, Ubuntu 24.04), release ep5-20261119T040026Z; comandos ejecutados como root en /opt/pedidos360/current mediante SSM Run Command (AWS-RunShellScript, script revisado deploy/ep5-evidence.py). Kafka UI consultado por su API en 127.0.0.1:8090 desde la propia instancia (la misma vista que se abre por reenvío de puertos SSM).

Resultado esperado (informe)
HTTP 201; fila con published_at no nulo; log con tópico, partición y offset; mensaje con clave orderId y payload OrderRegisteredStreamV1 con sus líneas.

Resultado observado
El usuario registró desde la SPA (sesión Entra, https://az3h2vqgsi.execute-api.us-east-1.amazonaws.com/app/) el pedido d9d1058b-145c-4396-8f4a-87e03a9a2e61 con 2 × Café de especialidad + 1 × Taza de cerámica (30.970 CLP) a las 14:05:40Z. API Gateway registró POST /api/v1/pedidos 201. order_stream_outbox: evento 4e172649-cccf-4f45-88a1-1ca5bbe0d10b con published_at 14:05:43.408 (1 intento, sin error). Log de orders-service (KafkaOutboxRelay): PUBLISH_CONFIRMED eventId=4e172649… orderId=d9d1058b… topic=pedidos360.orders.registered.v1 partition=2 offset=0. En el tópico, el mensaje de la partición 2, offset 0, tiene clave = orderId y un payload OrderRegisteredStreamV1 (schemaVersion 1, eventId, orderId, tenantId, occurredAt, currency CLP, total 30970.00, itemCount 2 y dos líneas con productId, productName, quantity, unitPrice y lineTotal), sin encabezados de tipo. Los tres grupos lo consumieron (CONSUME_OK) y el agregador publicó las métricas de ambos productos en version 1. El mismo pedido salió también por la outbox RabbitMQ (evento 3053af70…, ver E-16).

Diferencias con el informe
Ninguna en el resultado. El mensaje se muestra con kafka-console-consumer (partición y offset explícitos, sin grupo de consumidores, heap acotado), filtrado por la clave orderId, en lugar de la pantalla Kafka UI → Messages; el contenido es el mismo. Para no exponer el oid del usuario, la consulta de purchase_orders no incluye owner_subject.
