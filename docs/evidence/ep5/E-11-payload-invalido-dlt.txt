Evidencia E-11. Payload inválido derivado al DLT sin bloquear la partición

Objetivo
Comprobar el tratamiento de mensajes defectuosos.

Indicador asociado
EP5: manejo de errores (12 %).

Entorno
AWS cuenta 647660738152 (us-east-1), EC2 i-01bcf3ef9d3a64d4e (t3.large, Ubuntu 24.04), release ep5-20261119T040026Z; comandos ejecutados como root en /opt/pedidos360/current mediante SSM Run Command (AWS-RunShellScript, script revisado deploy/ep5-evidence.py). Kafka UI consultado por su API en 127.0.0.1:8090 desde la propia instancia (la misma vista que se abre por reenvío de puertos SSM).

Resultado esperado (informe)
Log CONSUME_DLT sin reintentos; mensaje en pedidos360.orders.registered.v1.DLT con encabezados de tópico, partición, offset y excepción; el pedido válido posterior se procesa con normalidad.

Resultado observado
Se envió a pedidos360.orders.registered.v1 un registro con clave e11-invalid-141647 y valor JSON inválido ('{"eventId": no-es-json'), que quedó en la partición 0, offset 0. sales-aggregator y order-monitor registraron de inmediato CONSUME_DLT eventId=unknown ... code=DESERIALIZATION_FAILED retried=false, sin ningún CONSUME_RETRY. pedidos360.orders.registered.v1.DLT recibió dos copias en la misma partición 0, una por cada grupo que falló (encabezado kafka_dlt-original-consumer-group). Los encabezados decodificados indican tópico original pedidos360.orders.registered.v1, partición 0, offset 0, timestamp original, excepción org.springframework.kafka.support.serializer.DeserializationException y mensaje 'failed to deserialize'. La partición no quedó bloqueada: el agregador confirmó el offset 1 en p0 y el siguiente pedido válido de esa partición (e1bb7872…, offset 1, durante E-10) se procesó con normalidad (CONSUME_OK ACCUMULATORS_UPDATED).

Diferencias con el informe
Ninguna. Como describe la sección 9, hay una copia en el DLT por cada grupo que falla (encabezado kafka_dlt-original-consumer-group). Los encabezados numéricos de Spring (partición, offset, timestamp) son binarios y se muestran decodificados (int32/int64 big-endian).
