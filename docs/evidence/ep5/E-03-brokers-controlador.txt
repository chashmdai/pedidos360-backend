Evidencia E-03. Brokers registrados y controlador

Objetivo
Comprobar el registro de los tres brokers y la existencia de un controlador.

Indicador asociado
EP6: arquitectura Kafka (10 %); Kafka UI (5 %).

Entorno
AWS cuenta 647660738152 (us-east-1), EC2 i-01bcf3ef9d3a64d4e (t3.large, Ubuntu 24.04), release ep5-20261119T040026Z; comandos ejecutados como root en /opt/pedidos360/current mediante SSM Run Command (AWS-RunShellScript, script revisado deploy/ep5-evidence.py). Kafka UI consultado por su API en 127.0.0.1:8090 desde la propia instancia (la misma vista que se abre por reenvío de puertos SSM).

Resultado esperado (informe)
Lista [1, 2, 3]; Kafka UI muestra tres brokers en línea y uno marcado como controlador.

Resultado observado
zookeeper-shell ls /brokers/ids devuelve [1, 2, 3]; get /controller indica brokerid 2 (modo ZooKeeper, kraftControllerEpoch -1). Kafka UI (API de la vista Brokers) muestra el clúster pedidos360 ONLINE con 3 brokers (kafka-1..3:29092), activeControllers=2, 62 particiones en línea, 0 fuera de línea, 0 subreplicadas y 186 réplicas en ISR.

Diferencias con el informe
Ninguna.
