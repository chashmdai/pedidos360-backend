Evidencia E-04. Kafka UI levantado y conectado

Objetivo
Comprobar que Kafka UI se ejecuta con su Compose propio y administra el clúster.

Indicador asociado
EP5: Compose de Kafka UI. EP6: Kafka UI (5 %).

Entorno
AWS cuenta 647660738152 (us-east-1), EC2 i-01bcf3ef9d3a64d4e (t3.large, Ubuntu 24.04), release ep5-20261119T040026Z; comandos ejecutados como root en /opt/pedidos360/current mediante SSM Run Command (AWS-RunShellScript, script revisado deploy/ep5-evidence.py). Kafka UI consultado por su API en 127.0.0.1:8090 desde la propia instancia (la misma vista que se abre por reenvío de puertos SSM).

Resultado esperado (informe)
Contenedor kafka-ui healthy; clúster pedidos360 en línea con tres brokers y los tópicos de la sección 5.

Resultado observado
Contenedor kafka-ui (kafbat/kafka-ui:v1.5.0 fijado por digest) healthy, publicado solo en 127.0.0.1:8090. Inicio de sesión LOGIN_FORM correcto con las credenciales generadas en la instancia (no impresas). Clúster pedidos360 ONLINE, 3 brokers, 5 tópicos (los 4 de la sección 5 más __consumer_offsets, que la lista oculta por ser interno).

Diferencias con el informe
Ninguna en el resultado. La parte Kafka UI se registra como texto desde la API de Kafka UI (/api/clusters/...), con sesión LOGIN_FORM abierta en la propia instancia: es la misma información que muestra la pantalla al abrirla por reenvío de puertos SSM a 127.0.0.1:8090.
